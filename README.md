## 这个项目在解决什么问题

出海达人营销（KOL / KOX）的钱，很大一部分浪费在**投前**：

达人自称做 3C，实际内容在做美妆；粉丝 200 万但互动率 0.3%，一眼买粉；受众 80% 在印尼，而你要投沙特。这些问题在投放后看数据能发现，但钱已经花了。行业里最朴素的做法是**按粉丝量降序选人直到花完预算**——本项目把它作为对照基线，实测在 $245,000 预算下，这种做法有 **32.5% 的钱花在了水号和高风险达人身上**。

KOXPilot 做的事：在签合同之前，把"这个达人能不能投、值多少钱、为什么"算清楚，并且**每个结论都能点开看到证据**——命中了哪条规则、实际值多少、同组阈值多少。

不是"AI 帮你选人"，而是**"AI 告诉你为什么不选他，以及不选他省了多少钱"**。

## 30 秒看懂

```
一句话 brief
   ↓  A1 BriefAgent      自然语言 → 结构化 CampaignSpec（LLM）
   ↓  A2 RecallAgent     5,000 达人库 → 定向候选池（规则）
   ↓  A3 GateAgent       四层质量门禁 G0→G1→G2→G3（规则 + 动态分位数阈值）
   ↓  A4 FitAgent        语义适配打分（正式链路=规则版；LLM 版在构建期真调、仅作离线对照，理由见下）
   ↓  A5 BudgetAgent     带硬约束的预算分配（规则 + 贪心修补）
   ↓  A6 AuditAgent      成本审计 + 反事实价值审计
投放清单 + 预算分配 + 风险证据链 + "比基线多省了多少钱"
```

| 三档判定准确率 | **0.6590**，macro F1 **0.6731** |
| reject 档 | P **0.8104** / R **0.7203** / F1 **0.7627** |
| pass 档 precision | **0.9466**（放过的人里 94.7% 确实干净） |

分欺诈类型的严口径召回：买粉 0.797（AUC 0.919）/ 互赞群 0.670（0.880）/ 机器评论 0.640（0.893）/ 刷播放 0.473（0.794）。

### 业务价值：卖的不是"多赚多少"，是"少烧多少"

先说结论，包括不利于我自己的那部分。

三个 campaign 合计 $245,000 预算，对照"按粉丝量降序选人"的行业朴素基线：

| | 单次实测（seed 20270919） | **12 种子稳健区间** |
| --- | --- | --- |
| 少浪费占预算 | −32.5%（$79,719） | **−21.5% ± 13.7%**（95% CI 12.8%~30.2%） |
| 有效曝光 | +98.6% | **+97.3% ± 54.6%** |
| 跑输基线的种子数 | — | **1/12（总口径）** |
| 选中达人数 | 基线 18 人 → KOXPilot 181 人 | — |
| 硬约束满足 | 3/3 campaign 全部满足 | 全部种子均满足 |

**那个 32.5% 是 12 个种子里第 2 高的观测，落在均值的 95% CI 之外。** 方向可信（11/12 为正，p=2.0e-4），但幅度被单次采样高估了约 50%。追加的 24 种子复核进一步降到 **19.1% ± 18.6%**，说明 21.5% 可能仍然偏乐观。我把这个数字写在这里，而不是继续挂着好看的 32.5%。

浪费金额与有效曝光**全部按 ground truth 计算，不使用引擎自己的分数**——否则就是自己给自己打分。

#### 这 21.5% 里，门禁到底占多少？

"少浪费"这件事里混着两个原因：**不把钱压在少数头部大号上**（结构分散化）和**识别水号并按质量排序**（门禁）。为了把它们拆开，加了一条第三臂 `diversified_no_gate`：与基线同一个候选池、强制 KOXPilot 的分层/地域/单人配额、但排序只看"每美元名义曝光"，**全程不读门禁判定与真实性折扣**。于是 `总差额 = (第三臂 − 基线) + (KOXPilot − 第三臂)`：

| 12 种子 · 少浪费金额 | mean ± std | 为负的种子 |
| --- | --- | --- |
| 合计 | $52.7k ± $33.4k | 1/12 |
| 其中**门禁与质量排序** | **$40.0k ± $12.6k**（CV 0.31） | **0/12** |
| 其中结构分散化 | $12.6k ± $39.0k（CI 跨 0） | **4/12** |

**稳定的那一段是门禁，不是分散投放**——而定稿单种子上看起来正好相反（分散化 $56.2k vs 门禁 $23.5k），我原本的猜测被自己的数据推翻了。三条必须一起说的反面事实：① 第三臂的**绝对**有效曝光在 12/12 个种子上都高于 KOXPilot（它专挑 CPM 最便宜的长尾，而 KOXPilot 会主动放弃便宜但不对味的曝光），所以三臂可比的口径是浪费金额与有效曝光率；② 第三臂平均选 **516 人**，真实采购里不可执行，它只是对照臂不是方案；③ "门禁贡献"其实是"门禁过滤 + 质量排序"的合计，两者共用同一批分数，不再拆得开。详见 [docs/06 表 1 附](docs/06-robustness.md)。

#### 但真正的价值不在均值，在方差

同一实验量化了另一件事：**基线是高方差赌博。**

| | 基线（按粉丝量选人） | KOXPilot |
| --- | --- | --- |
| 浪费率跨种子 std | **33.6%** | **4.7%**（小 7.2 倍，p=2.7e-21） |
| 有 25% 的局，浪费率 | **> 50%**（最惨一局 99.9%） | **从未超过 14.8%** |
| 有 42% 的局，浪费率 | < 5%（抽到好牌） | — |

决定性的证据：KOXPilot 输的那几局，基线的浪费率都 ≤ 5.6%（本来就没踩坑，没什么可省）；而基线爆掉的 9 局里，KOXPilot **9/9 全胜**。

所以这套东西的产品价值不该翻译成"帮你多赚 21.5%"，而是：**把"四分之一的概率烧掉一半预算"这个尾部风险，换成稳定的约 4% 浪费。** 代价是在基线本来就抽到好牌的局里小输一点。对一个毛利率只有 2.63% 的投放代理业务来说，消灭尾部灾难比提高均值更值钱。

门禁能力本身则高度稳定，不依赖种子：fraud F1 **0.7275 ± 0.0090**、AUC **0.8878 ± 0.0054**、三分类准确率 **0.6679 ± 0.0051**（CV ≤ 0.023）。**波动来自"基线只选 5 个人"的极小样本对照臂，不是来自模型能力。**

#### 顺带一个不利于自己的发现

单种子报出的弱项清单里，只有 `follower_bucket = mega` 是跨种子稳定的系统性短板（11/12 个种子进榜，p=1.5e-07）；`country = SA` 与 `platform×bucket = youtube|macro` 是**采样噪声**（p=0.132 / 0.803）。

这是典型的 winner's curse：**单次实验里"最差的那几格"，大部分只是运气差，不是真短板。** 完整数据见 [docs/06-robustness.md](docs/06-robustness.md) 与 `output/multiseed.json`（`make multiseed`，纯确定性，约 30s 可复跑）。


### 该不该用大模型：用实验回答，不用立场回答

同一批 600 样本、同一 ground truth、唯一变量是 system prompt：

| 方案 | Precision | Recall | F1 | token |
| --- | --- | --- | --- | --- |
| 规则对照组（20 行 Jaccard 规则） | 0.419 | 0.857 | **0.562** | **0** |
| Prompt v1 朴素版 | 0.237 | 0.845 | **0.363** | 434,018 |
| Prompt v2 加负例约束 | 0.355 | 0.786 | **0.489** | 467,327 |
| Prompt v3 定义业务判据（生产版） | 0.614 | 0.798 | **0.691** | 492,460 |
| 最优单组合 v3 × Azure | 0.688 | 0.786 | **0.733** | — |

**前两版 Prompt 都输给了零成本的规则基线。** 只有 v3 反超，而 v3 的关键改动不是加咒语、不是给更多例子，是把判据从「标签是否一致」改写成「**投放方按 declared 选人会不会选错**」——从技术口径改成业务口径。

这张表的形状（先输后赢）本身就是结论：**能写 prompt ≠ 会写 prompt，差别在于有没有把业务判据想清楚。**

> ⚠️ 诚实记录一处混淆变量：v3 同时改了两件事（判据业务化 + 品类邻接表从举例改为完整注入），v2→v3 的增益无法严格归因到单一改动。详见 [docs/04-prompt-and-cost.md](docs/04-prompt-and-cost.md)。

### 真实成本账

`output/llm_bench.json`，全部取自各 API 返回的 `usage` 字段，**非估算**：

172 次调用 · 总 token **1,103,473**（其中 reasoning token **403,202**）· 平均 6,415 token/次 · 耗时 939s · 相对全 LLM 方案调用量缩减 **3.95×**。

其中 1 个 batch 调用失败，按"未覆盖"处理（该模型覆盖率记为 0.98），**没有用默认值填充冒充成功**。

## 四层质量门禁

门禁只能看到**可观测字段**，看不到 ground truth（这一条由 AST 静态扫描测试强制保证）。

| 层 | 判什么 | 代表规则 |
| --- | --- | --- |
| **G0 完整性** | 数据够不够做判断 | 关键字段缺失率、报价缺失、受众地域缺失 |
| **G1 真实性** | 是不是水号 | 互动率偏离同组分位数、粉丝增长突刺 vs 自然爆红、评论机器人特征、播放/粉丝比异常 |
| **G2 一致性** | 自称与实际是否对得上 | 标签错配、三源标签冲突、受众地域/语言与 campaign 目标错配 |
| **G3 品牌安全** | 能不能让品牌露脸 | 高风险内容、争议历史、竞品合作、受管制品类资质 |

### 一个设计要点：阈值是分组标定的，不是全局固定的

TikTok 的 nano 达人和 YouTube 的 mega 达人，互动率基线天然差一个数量级。用一个全局阈值判"互动率异常"，等于系统性地冤枉一类人、放过另一类人。

所以阈值按 **(platform × follower_bucket) 分 25 组**、在库内标定分位数（`output/thresholds.json`）。证据链里输出的不是"互动率 0.4% 偏低"，而是"**互动率 0.4%，低于 tiktok|macro 组 p10 的 1.2%**"——这句话投放方能直接拿去和达人对质。

## 前后端双实现一致性

前端不是读一份预先算好的静态结果来演戏。四层门禁在**浏览器里用 TypeScript 重新算一遍**，和 Python 版读同一份阈值表（TS 侧不做任何再标定）。

每次 `pnpm run refresh` 会把 TS 引擎对全库 5,000 条的判定与 Python 的 `output/verdicts.json` 逐条比对，结果落盘到 `web/public/data/consistency.json`，页面直接读取：

```
total 5000 · matched 5000 · diff_count 0 · match_rate 1.0
比对字段：verdict / group_key / rules[] / completeness / authenticity / consistency / brand_safety / fraud_score
```

**这个数字是脚本生成的，不是写死在组件里的。** 改坏任一侧实现，`refresh` 就会红。

## 我自己抓到并修掉的问题

一个只展示漂亮指标的作品是可疑的。下表这 10 个缺陷是我自己在开发过程中发现并修掉的，其中两个是**评测自证**——ground truth 和特征其实是同一个东西的两面，于是朴素方法就能拿到近乎完美的指标。这类问题不会报错，只会给你一个漂亮得不真实的数字。

| # | 问题 | 表现 | 修完的代价 |
| --- | --- | --- | --- |
| 1 | 标签错配的 ground truth 等价于"两个集合是否相交" | 规则基线 **P=R=F1=1.000** | 规则基线 F1 掉到 **0.562** |
| 2 | 观测模型是整块替换，正例 Jaccard 只有 0 和 1 两个取值 | 5 个 arm 的召回**精确相同**（0.857），尽管彼此预测差异 146/600 | 召回重新变成真实 tradeoff |
| 3 | LLM 缓存 key 只 hash `kox_id`，不 hash 内容 | 重新生成数据后旧预测被静默复用，**不报错只给错结论** | 旧缓存全部失效（正确行为） |
| 4 | 评测表里拿"库级中性 spec"去报只有具体 campaign 才有意义的指标 | 语义适配分位数**全是 1.0**，一格假装有意义的数据 | 分布恢复区分度（p10 0.20 / p50 0.65） |
| 5 | 招牌价值数字只跑了一个种子 | 32.5% 看着很硬，实际是 12 个种子里第 2 高的观测 | 改口径为 **21.5% ± 13.7%**，并承认 1/12 种子跑输基线 |
| 6 | 弱项清单没做显著性检验 | 报了 6 条弱项，实际只有 1 条是真的 | 其余定性为采样噪声（winner's curse） |
| 7 | 反事实只有两臂，"少浪费"无法归因 | "32.5% 是门禁省下来的"这句话在两臂产物上**没有证据**，差额里混着结构分散化 | 补第三臂 `diversified_no_gate` 后拆开：门禁与质量排序 **$40.0k ± $12.6k**（12/12 为正），结构分散化 $12.6k ± $39.0k（**4/12 为负**、CI 跨 0）——原来的猜测被推翻 |
| 8 | "我们用 LLM 做语义适配"这句话在正式链路里站不住 | `llm_cache.json` 有 260×3 条真实 LLM 适配分，而 `make eval` 每个数字都来自 `rule_fit_score`；文档只"承认"落差、没有任何数字，既无法验证也无法被推翻 | 补 `eval/llm_fit.py` 做量化对照：覆盖率 **14.9%**、双算率 **97.1%**、覆盖子集上 LLM 分只降不升 → 结论"继续用规则版"由判据算出（三项全过会自动翻成可升格），并真跑了注入反事实（判定只翻 1 条、合计少浪费 $735，不作为招牌数字） |
| 9 | 产物里"这些 token 是哪个模型跑的"有两个答案 | `llm_bench.models.ark` 写的是 endpoint id（`ep-2026…`），`per_task[*].model` 写的是服务端型号（`doubao-…`）；两处都叫 `model`，照着前者写材料就会说出"我们用的模型是 ep-2026…"——那是资源 id 不是模型 | 补 `llm/identity.py` 把两个概念拆成 `requested_model_id` / `served_models`，对外只报服务端型号；判据只看"名字是谁说的"，不做 `ep-` 前缀之类的模式匹配；调用全失败时如实标 `requested_id_only`。回归测试从产物现取请求 id，断言它在 `metrics.json` 里只出现在 `requested_model_id` 上 |
| 10 | 预算模型里的关键假设 `decay=0.7` 长期**没有任何证据** | `budget/policy.py` 里 `POST_DECAY_SCAN = (0.5, 0.7, 0.9)` 这个常量定义了很久、注释也承诺给三档结果，但产物里从来没有它——也就是"同一达人第 n 条内容的边际曝光衰减"这个**建模假设**（不是观测值）一直无人验证，而所有预算与反事实数字都建在它上面 | 补 `eval/decay_scan.py` 真跑三档（共用同一批 GateResult，逐档重跑三臂 + gt 审计）。结论必须两半一起说：**价值结论不依赖它**（合计少浪费离差仅 **1.4%**、两段归因符号逐档不翻转），**但选谁会变**（选中名单 Jaccard 最低 0.826、金额加权重叠最低 **0.651**，低于自设 0.8 判据）→ 判定 `value_conclusions_hold_but_selection_shifts`。且这条扫描**回答不了**"哪一档更接近真实世界"，产物里专门有字段和测试堵住这个过度解读 |

修复的代价是数字全面变差，我照实采用：

| 指标 | 早期 | 最终采用 |
| --- | --- | --- |
| 规则基线 F1 | 1.000 | **0.562** |
| 少浪费金额 | $104,239（42.5%） | **$79,719（32.5%）** |
| 有效曝光提升 | +133.6% | **+98.6%** |
| 阈值敏感性最大 F1 偏移 | 0.0523（不稳健） | 0.0582（**仍不稳健**） |

最后一条：±20% 阈值扰动下最大 F1 偏移 0.0582，按我自己设的判据（≤0.05 才算稳健）**是不达标的**。我没有把判据放宽到 0.06 让它变绿——改判据等于改考卷。

完整过程见 [docs/03-evaluation.md](docs/03-evaluation.md) 的「反自证」专章。

### 代码级保证

- **AST 静态扫描测试**：遍历 `gates/` `budget/` `llm/` 的所有源文件，断言不存在对 `gt` / `true_categories` / `is_fraud` / `fraud_type` 等字段的任何访问。门禁想作弊，测试先红。
- **泄漏哨兵测试**：断言朴素 Jaccard 规则的 F1 必须 < 0.95，且正例的 Jaccard 分布不得退化成双峰。

## 已知弱项（没有藏在末尾）

经 12 种子稳健性实验区分了**系统性短板**与**采样噪声**——这个区分很重要，前者说明设计有短板（可改进），后者不该当成结论：

| 弱项 | 单种子数值 | 跨种子性质 |
| --- | --- | --- |
| `follower_bucket = mega` 水号识别 | F1 **0.467**（P 0.342 / R 0.737） | ✅ **系统性短板**（11/12 种子进榜，delta −0.197，p=1.5e-07）。头部达人样本少、互动率天然偏低，与买粉特征混淆 |
| `country = SA` | F1 0.476（P 0.833 / R 0.333） | ⚠️ **采样噪声**（p=0.132），不构成结论 |
| `platform × bucket = youtube\|macro` | F1 0.476 | ⚠️ **采样噪声**（p=0.803），不构成结论 |
| 阈值敏感性 | ±20% 扰动最大 F1 偏移 **0.0582** | 判定为**不稳健**，未达自设的 0.05 判据 |
| 标签错配存在**召回天花板** | — | 部分正例的观测被 bio 完全带偏，只看 declared + observed 无法检出。要突破必须引入第三方信号（实际带货商品类目、评论语义） |
| 反事实价值的**幅度不稳** | 单次 32.5% | 12 种子 21.5% ± 13.7%，24 种子 19.1% ± 18.6%，1/12 种子跑输基线 |
| 结构分散化的贡献**不显著** | 单次看起来占 70% | 12 种子 $12.6k ± $39.0k、4/12 为负、CI 跨 0；稳定的那一段是门禁与质量排序（$40.0k ± $12.6k） |
| 投放**名单不唯一** | — | `decay` 是建模假设。三档扫描下价值结论稳（离差 1.4%），但选中名单金额加权重叠最低 **0.651**——换个假设就换一批人。名单应读作"给定假设下的方案"，不是最优解 |

反向扫描 45 个合格分层，只有 1 个系统性短板 + 1 个"轻微但一致"（`country = BR`）。**换句话说，我单种子那份弱项清单里大部分是运气差，不是真短板**——这正是 winner's curse。

模型对比数字均为**单次实测值**，不是均值±方差——推理模型默认非贪心解码，实测同配置两次 F1 有 0.653 vs 0.681 的波动。结论层面（v3 > v2 > v1、LLM > 规则）是稳的，小数点后第二位不稳。

## 工程边界

| 环节 | 性质 |
| --- | --- |
| 达人数据 | **合成数据**，5,000 条，固定种子可复现。真实达人数据涉及商业敏感与隐私 |
| 四层门禁 / 预算分配 / 评测 | **确定性计算**，无 API key 即可完整复跑 |
| brief 解析 / 标签错配判定 | **构建期真调 LLM**，结果固化进 `output/llm_cache.json`；线上 Demo 读固化结果，公网零外部依赖 |
| 语义适配打分（A4） | **正式链路走规则版 `rule_fit_score`**；LLM 版真调过、只作离线对照。不升格的三条判据（覆盖率 14.9% / 双算率 97.1% / 覆盖子集上只降不升）由 `eval/llm_fit.py` 现算，落在 `metrics.json.table_6_llm_vs_rule.semantic_fit_llm_vs_rule` |
| 前端门禁引擎 | **浏览器内实时计算**（TypeScript），与 Python 版逐条比对 0 差异 |

**合成数据能证明什么**：方法论、工程完整度、评测严谨度、能否发现自己的错误。
**不能证明什么**：真实分布下的绝对指标。这一点我不打算含糊。

详见 [docs/05-boundaries.md](docs/05-boundaries.md)。
