# KOXPilot 前端亮色改版设计规范（v2）

这一版要解决的三个具体问题（用户原话）：

1. **「做的太杂，感觉像堆砌各种功能」** —— 6 个 tab 共 23.7 屏内容，全部平铺，没有主次。
2. **「人一下子看上去不知道有啥功能」** —— 落地页是一个 brief 选择器 + 6 张日志卡，
   没有任何地方回答「这东西是干嘛的、输入什么、输出什么」。
3. **「界面做的也不好看，颜色亮一点」** —— 近黑底 + cyan 发光，11~12px 灰字，读着累。

改版原则一句话：**先让人 10 秒看懂它干什么，再让愿意深挖的人挖得到底。**
现有内容一条都不许删（那是这个作品的全部价值），但必须按「结论在前、论证折叠」重排。

---

## 一、色彩系统

已在 `tailwind.config.js` 与 `src/index.css` 落地，**不要再自己造色**。

| 用途 | token | 值 | 说明 |
| --- | --- | --- | --- |
| 页面底 | — | `#f6f8fc` + 两团淡靛蓝/天蓝径向渐变 | 已在 body，不要覆盖 |
| 卡片 | `.card` | 白底 + `border-slate-200/90` + `shadow-card` | 所有面板统一用它 |
| 卡内分区 | `.subcard` | `bg-slate-50/70` + `border-slate-200/80` | 卡片里再分块时用 |
| 主色 | `brand-*` | 靛蓝 `#4f46e5`(600) | 交互、选中态、主按钮 |
| 真算色 | `live-*` | 天蓝 `#0ea5e9`(500) | **专用于「浏览器内真算」语义**，别乱用 |
| 通过 | `emerald-600` | `#059669` | verdict.pass |
| 待审 | `amber-600` | `#d97706` | verdict.review |
| 拒绝 | `rose-600` | `#e11d48` | verdict.reject |

**亮色下的铁律**（和暗色完全相反，改的时候盯住）：

- 文字必须**深**：标题 `text-slate-900`，正文 `text-slate-700`，次要 `text-slate-600`，弱 `text-slate-500`。
  **禁止** `text-slate-300/400` 当正文——在白底上等于没有。
- 描边用**实色浅灰** `border-slate-200/300`，禁止 `border-white/10`（白底上不可见）。
- 彩色底用该色系 `50`/`100` 实色，禁止 `bg-*-400/10` 这类蒙版（亮底上脏）。
- 层次靠**阴影**（`shadow-card` → `shadow-lift` → `shadow-pop`），不靠发光描边。

## 二、字号系统

原版大量 10~11px，是「读着累」的直接原因。新的下限：

| 角色 | class | 大小 |
| --- | --- | --- |
| 英雄数字 | — | 32~44px `font-semibold` `num` |
| 卡片主数字 | — | 24px |
| 区块标题 | `.section-title` | 15px semibold slate-900 |
| 正文 | `.body-text` | 13px slate-700 |
| 表格 | `.td` / `.th` | 13px / 11px |
| 说明 | `.muted` | 12px slate-500 |
| 标签 | `.chip` | 11px |

**10px 只允许出现在角标/图例，正文一律 ≥12px。**

## 三、信息架构：结论在前，论证折叠

这是本次改版的重点，比换色重要。

### 折叠纪律

每个论证型区块拆成两层：

- **上层（默认展开）**：一句话结论 + 关键数字 + 最多 2 行说明。
- **下层（默认折叠）**：控制变量、可信边界、口径澄清、反面事实、长表格、trace 日志。
  用统一的 `<Collapse>` 组件，标题写清里面是什么，例如
  「展开：为什么这个增益不能严格归因（混淆变量）」。

**折叠不等于藏**。折叠标题必须自带信息量，让人扫标题就知道我考虑过这件事。
尤其是自我批判类内容（可信边界 / 混淆变量 / 低支撑格 / 伪重复），
标题要显式点出来——这些是加分项，只是不该占满第一屏。

### 每个 tab 的第一屏必须回答

进入任意 tab，不滚动就能看到：**这一页在证明什么 + 结论是什么**。
做法：tab 顶部一条「本页结论」横幅（`.card`，左侧 4px 品牌色竖条），
一句话 + 2~4 个关键数字。然后才是论证。

## 四、必须保留的诚实性设计

改版**不得**削弱下面这些，它们是这个作品的立身之本：

- `TruthChip`（浏览器内真算 / 构建期真调 LLM·结果固化 / 以 gt 为裁判的审计 / 合成数据）
  必须继续贴在每个对应区块上，位置要显眼。
- `MissingArtifact` 的诚实空态不许改成占位数字。
- 所有「可信边界」「混淆变量」「不能归因」「低支撑」的自述，一条都不许删，
  只允许折叠，且折叠标题要点明。
- 实测耗时（`performance.now()`）、token 账、sha256 继续展示。

## 五、组件约定

- 新增共享组件放 `src/components/`，命名 PascalCase，必须有中文 doc 注释说明「为什么需要它」。
- 图表颜色统一从 `src/components/palette.ts` 取，禁止在组件里写死 hex。
- 所有交互元素加 `.focusable`，保证键盘可达。
- 动画克制：只保留 `fade-up` 入场和数字 `CountUp`，不要循环发光。

## 六、验收标准

改完必须同时满足：

1. `pnpm run build` 通过（`tsc -b` 零错误）。
2. `pnpm run verify` 通过，且 `consistency.json` 里 Python/TS 差异仍为 **0 条**
   ——**视觉改版绝对不能碰 `src/engine/` 与 `src/budget/` 的计算逻辑**。
3. 单 tab 全页高度 ≤ 3.2 屏（1000px 视口），即 ≤ 3200px。
4. 白底上没有 `text-slate-300/400` 当正文；没有 `border-white/*`。
5. 截图逐屏看一遍，不许有对比度不足、色块脏、文字压边、图表网格线不可见。
