# KOXPilot 前端设计规范（v3）

## 这一版是在推翻 v2 的一条错误原则

v2 的原则是：**「现有内容一条都不许删（那是这个作品的全部价值），但必须按结论在前、论证折叠重排」**。

这条是错的，而且是这一轮返工的直接原因。按它执行的结果是：把一本工程日记折叠起来贴在产品界面上。评审看到的是

- 「v3 的 +0.2016 增益不能严格归因：我同时改了两处，没补只改一处的消融实验」
- 「可信边界：同 prompt 同模型两次跑出的 F1 不同（实测 0.653 vs 0.681），所以小数点后第二位不稳」
- 「失败的 batch 按未覆盖处理，不用默认值填充」
- 「口径改过之后数字更难看，照实采用」
- `keep_rule_fit_in_formal_chain`（原始代码标识符直接露在页面上）
- 每个折叠块上挂着「自述局限」角标

**折叠解决了"占地方"，没解决"不该在这儿"。** 这些内容不是排版问题，是**放错了容器**。

## 一、核心原则：产品界面是产品，工程日记进文档

判断一段文案该不该留在 Demo 里，只问一个问题：

> **这句话是在帮使用者做决定，还是在为项目本身辩护？**

帮使用者做决定的留下。属于自证的，搬进 PDF / README / `docs/`。

**这不是丢掉，是搬家。** 落脚点已经齐备，不许以"会丢失价值"为理由拒绝删除：

| 内容 | 新家 |
| --- | --- |
| Prompt 三版横评、token 真实用量账、LLM vs 规则 | `docs/04-prompt-and-cost.md`（1.4 万字） |
| 可信边界、口径冲突、混淆变量、分层交付降级 | `docs/05-boundaries.md`（2.1 万字） |
| 多种子稳健性、伪重复口径、敏感性扫描 | `docs/06-robustness.md`（2.0 万字） |
| 构建期自查修复日志、缺陷清单 | README「开发过程中自查发现并修掉的问题」13 条 |
| 最诚实的弱项 | PDF 第 1 页（不在附录，在第一页） |

需要深入核验时，材料一份不少。但**产品界面不是自证的地方**。

## 二、四类必须从界面清掉的文案

### 1. 防御性自证（最伤，优先清）

「这不是录像」「没有第三种来源」「不是写死的」「非估算」「不是事后检查」「防自证」「绝不」「一次都不许有」。

**没人指控你，你先喊冤，只会让人觉得你心虚。** 一个自信的产品不解释自己不是假的。

替换方式不是换个说法，而是**直接展示**：实时重算的耗时数字本身就是证据，双实现差异 0 条摆在那里就是证据。**证据不需要旁白。**

### 2. 开发过程叙述

「构建期」「迭代日志」「历史值」「自我修复」「踩过的坑」「我原本以为」「被自己的实验推翻」「照实采用」「收口阶段才抓到」「原来的处理是」「这一版/上一版」。

这是研发过程，不是产品能力。**使用者不关心你怎么走到这一步的。**

### 3. 内部工程遥测

逐 arm 精确率/召回/F1 明细表、token 分解（prompt/completion/思维链）、失败 batch 计数、口径重叠双算率、注入后判定翻转数、sha256 产物清单、字段自检表、守护测试条目、`performance.now()` 之外的性能账。

**这些是 CI 报告和复现材料，不是产品界面。**

### 4. 原始代码标识符

`keep_rule_fit_in_formal_chain`、`G2.4/audience_match`、`pooled_p_value_usable`、`selection_stable`、`honesty_notes` 这类字段名/枚举值一律不许直接显示。要么翻成业务中文，要么删。

## 三、允许保留、且应该保留的「边界说明」

**不是把诚实全删掉，而是把"忏悔"改成"规格"。**

区别：

| ❌ 忏悔口吻（删） | ✅ 规格口吻（留） |
| --- | --- |
| 「我如实标了 stable=False 而不是调宽判据让它变 True」 | 「阈值敏感性：未达稳健判据」 |
| 「我自己承认的问题，扫标题就够，想深挖再展开」 | （删掉这个框，边界统一收进一处） |
| 「数字其实对 LLM 有利，我还是判了不升格」 | （整段进文档） |
| 「名单会随假设变动，不确定性我承认了」 | 「19 人 / 9.8% 预算需人工复核，其余可直接下单」 |

保留形式：**每个 tab 最多一个**「能力边界」区块，3~5 行，陈述句，无第一人称，无过程。写清"用这份结果时要注意什么"，不写"我做了什么努力才发现这件事"。

例如：

> **能力边界**
> · 数据为合成数据集（5,000 条，固定种子），绝对数值仅在该生成假设内成立
> · 阈值敏感性未达稳健判据，指标随阈值 ±20% 最大偏移 0.058
> · 名单中 19 人（9.8% 预算）随建模假设变动，标记为需人工复核

三行说完，体面，且信息量不比原来那一屏少。

## 四、去掉「自述局限 / 支撑证据 / 明细」角标体系

`Collapse` 的 `flag` 机制要移除。理由：**角标本身在宣告"这是一次自证审计"，而这正是错误的框架。** 折叠块保留（用于收纳次要明细），但不再打这类标签。

## 五、新的页签结构（4 → 3）

| tab | 内容 | 说明 |
| --- | --- | --- |
| **投放决策** | 输入 brief → 六 Agent 轨迹 → 名单与预算 → 与基线对照 | 产品主体，基本保留 |
| **效果验证** | 招牌指标 + 混淆矩阵 + F1 热力图 + 一个「能力边界」块 | 大幅瘦身 |
| **技术实现** | 六 Agent 编排 + Python/TS 双实现一致性 | 保留架构与一致性，清掉遥测 |

**删除整个「成本账」页签** —— 12 个区块几乎全是工程内部账（Prompt 版本横评、token 分解、逐 arm 表、三臂归因、decay 扫描）。其中唯一有产品价值的结论是「没有全用大模型：混合架构把调用量降到 1/3.95，质量代价 0.12 F1」，把这一条做成「技术实现」页里的一张卡，其余全部进 `docs/04`。

**删除整个「踩过的坑」14 条自查修复日志** —— 纯开发日记，README 已有 13 条缺陷表承接。

## 六、保留不变的部分

- 亮色设计系统、字号系统（v2 的一、二节仍然有效）
- 自由输入 brief 与浏览器内 A1–A6 实时重算
- Python/TS 双实现一致性面板（这是技术能力展示，不是自证——**但不要配旁白**）
- 数据全部来自产物 JSON，不写死
- 产物缺失时的诚实空态（保留机制，但文案改中性：「该项未生成」，不写「我不用默认值填充」）

## 七、验收标准

1. `pnpm run build` 通过，`pnpm run verify` 的 Python/TS 差异仍为 0 条（**不许碰 `src/engine/`、`src/budget/` 的计算逻辑**）。
2. 全站搜不到第二节列举的四类措辞。
3. 每个 tab ≤ 2.5 屏（≤2500px @1000px 视口）。
4. 以不了解这个项目的读者视角通读一遍：**通篇没有一句话是在为项目辩解。**
